# Claude Certified Architect Foundations— 学習プロジェクト設定

このファイルと、同じディレクトリの対になる設定ファイル（`CLAUDE.md` と `CURSOR.md`）は同じ内容にする。

## 試験シナリオ

練習問題を出す際は **必ず `quiz/Scenarios.md` のいずれかのシナリオを前提として問題を作成すること**。
シナリオは編集せず、そのまま使用すること。
シナリオの詳細は [`quiz/Scenarios.md`](./Scenarios.md) を利用する。
シナリオと問題と解答は英語、解説の依頼があった場合は日本語とする。
練習問題は本番レベルか、少し難し目の難易度で、選択肢は消去法で正解が選べないように紛らわしいものとすること。

問題文には、正解を一意に定めるために必要な制約を明示すること。特に以下の点が曖昧だと複数の選択肢が正解になりうるため注意する。

- 下流システムの要件（null を許容するか、欠損値を人間レビューに回すか等）
- 介入のレイヤー（プロンプトレベルか、スキーマレベルか、後処理か）
- 対象の優先基準（レイテンシ重視か、精度重視か等）

出題形式は、制約を箇条書きで示す形式と、制約を問題文の文章に溶かし込む形式のどちらかをランダムに選ぶ。どちらの形式でも、正解を一意に定めるために必要な制約は残す。直前の形式は確認しない。

正解の選択肢（A/B/C/D）の位置は毎回ランダムにする。LLMは正解をB・Cに配置しやすいバイアスがあるため、意識的にA・Dも正解になるよう分散させること。直前の問題の正解位置は確認しない。

## 練習問題の出し方

ユーザーは Claude の資格試験の勉強中である。「始めてください」、または練習問題を求められたら、次の手順で1問出す。

1. そのセッションの1問目を出す前だけ、[`quiz/Scenarios.md`](./Scenarios.md) と [`quiz/cursor_study_progress.md`](./cursor_study_progress.md) を読む。[`quiz/test_objectives.md`](./test_objectives.md) は、出題の前には読まない。2問目以降は、出題のためにこれらのファイルを読み直さない。
2. 出題ドメインは、ランダムとする。個別の TEST OBJECTIVE は、そのドメインの中でどの観点を問うかの参考にとどめる。
3. TEST OBJECTIVE の一覧、`scorereport.pdf`、試験ガイド、`練習問題_進捗.md` は読まない。チャットに TEST OBJECTIVE の英文を書き出さない。
4. `quiz/cursor_study_progress.md` の「シナリオ別出題数」を参照し、出題数が最も少ないシナリオを優先して選ぶ。同数の場合はランダム。選んだシナリオを前提にした、本番レベルの四択を1問出す。シナリオ文は `quiz/Scenarios.md` の記述をそのまま使い、要約・言い換え・変更しない。問題固有の制約は問題文に追加してよい。
5. シナリオ、問題、選択肢、解答は英語で書く。解説は、ユーザーが依頼した場合だけ日本語で書く。解説は短くする。
6. 解答はユーザーが答えるまで出さない。「分からない」と言った場合は、その時点で正解と解説を出す。
7. 出題と解説のチャット本文に、進捗ファイル、`quiz/Scenarios.md`、過去の問題文を再掲しない。
8. 間違った場合に、その問題に関する質疑応答となるため、次の問題は指示があるまで出さない。

## 学習進捗の更新

学習進捗は [`quiz/cursor_study_progress.md`](./cursor_study_progress.md) に記録する。全問の履歴は残さない。

ユーザーが1問答えるたび、または「分からない」と答えるたびに、次の問題を出す前にこのファイルを更新する。

1. 使用したシナリオの出題数を「シナリオ別出題数」で1増やす。
2. その問題を、次の5ドメインの1つだけに対応づける。
   - Agentic Architecture & Orchestration
   - Tool Design & MCP Integration
   - Claude Code Configuration & Workflows
   - Prompt Engineering & Structured Output
   - Context Management & Reliability
3. 対応する行の出題数を1増やす。正解なら正解数も1増やす。正答率は正解数 ÷ 出題数とする。未解答は不正解として数える。ドメインの合計と練習合計も更新する。更新は該当行と、必要な誤答メモだけを置換する。
4. 不正解または未解答のときだけ、そのドメインの誤答メモに、間違った観点を1行追加する。同じ観点のメモが既にあれば追加しない。正解のときはメモを追加しない。
5. 同じ観点で後から正答したら、その誤答メモは削除する。
6. 正誤に限らず出題したら、[`quiz/test_objectives.md`](./test_objectives.md) を読み、該当する目標を「未出題」→「出題済」に移動する。全て出題済になったら周回数を1増やして全項目を「未出題」に戻す。
7. 問題文、選択肢、解説、日付、シナリオ名、TEST OBJECTIVE の全文は記録しない。ファイル全体をチャットに再掲しない。
8. Cursor と Claude Code で並行して編集しているので、出題数や正答率の更新時には、単純にその時点のファイルの状態から更新すればよい。更新前の状態との比較は不要。

セッションをリセットしても、`quiz/cursor_study_progress.md` と `quiz/Scenarios.md` を読めば学習を継続できる。

## 出題スキップの管理

`quiz/cursor_study_progress.md` の「出題スキップ（習得済み）」セクションへの追記は、**ユーザーから明示的に指示があった場合のみ**行う。正解・不正解にかかわらず、自動的に追記してはならない。
